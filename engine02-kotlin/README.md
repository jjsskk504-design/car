# RISK RADAR Engine02 ? Kotlin-first research engine

This independent Kotlin/JVM module is intended to replace the Python Engine02
**runtime**, not to modify PRISM PART01 or frozen RiskFrame v1 contracts.

## Staged migration
1. Port causal Behavior V3 heuristics, risk geometry and offline event/holdout metrics to Kotlin.
2. Port AV2/NGSIM/CARLA adapters with strict timestamps, coordinates, provenance and uncertainty.
3. Port V2 physical simulator and data QA after Kotlin V3 unit tests pass.
4. Integrate with PRISM Kotlin prediction and vehicle modules through a reviewed adapter;
   then remove legacy Python snapshots from any final Android deployment.

The historical Python files in the separate engine02_preintegration_20261111
folder are **reference-only** and not packaged by this module.

## Run

From the module directory, with JDK 17+ and Gradle:

```powershell
gradle test --no-daemon
```

Target JVM bytecode level 17. This standalone JVM build is not an Android
APK or an in-vehicle runtime validation.

No raw CARLA, NGSIM, AV2 or Waymo files are included. This project makes no
real-world safety, calibrated probability, ADE/FDE, precision/recall, lead
time or false alerts/hour claim. These require independent authorized
ground-truth data, measured exposure and applicable licenses.

## PRISM VehicleFrame boundary

The adapter requires schema 1.0, explicit ego_local_m coordinates, unique
vehicle IDs, and externally verified, time-aligned body-center projections for
all actors in one road reference. Map projection and stable identity epochs
are upstream inputs. Use the same EngineParameters for adapter and inference.
Signal evidence needs a matching actor, timestamp, and observation scope.
The check uses the team's VehicleFrame DTO and JSON parser in a separate JVM
build. The main Engine02 artifact has no dependency on the replay module.

From engine02-kotlin:

```powershell
gradle -p contract-check test --no-daemon
```

This verifies the checked-out team contract source and the Engine02 boundary.
Android/Pleos app wiring and road projection from actual sensor data remain open.

## Reproduce the synthetic V3 comparison

The Kotlin suite runs against committed expected outputs generated by the
historical Python oracle. It compares intent labels, scores, features, overlap,
neighbor gaps, diagnostics, and research metadata across nine sequences.
Regenerate the fixture offline when updating the comparison:

```powershell
python -B tools/generate_v3_parity.py
gradle clean build --offline --no-daemon
```

Python is used only for fixture generation. The default-parameter comparison
covers the synthetic sequences in the fixture. Kotlin uses integer millisecond
thresholds, including custom thresholds where the Python seconds round-trip
can round down. The offline evaluator also provides missed-event rate, temporal
partition assignment, and the physical QA gate for synthetic scenes.
